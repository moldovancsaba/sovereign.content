## 1. Industry practices (what to copy)

### 1.1 Evaluate systems, not models alone

[MASEval](https://arxiv.org/pdf/2603.08835) (ACL 2026 demo): framework / orchestration / error-handling
choices move outcomes as much as model choice. For us that means scoring **timer shape, ingest
discipline, playbook honesty, HiTL policy** — not “which Cloud Agent model was used.”

### 1.2 Reliability needs traces + repeated-run signals

[MAESTRO](https://arxiv.org/abs/2601.00481): architecture dominates cost–latency–accuracy; runs can be
structurally stable yet temporally noisy. Practical takeaways:

- Capture **structured signals every day** (success/fail class, defer reasons, empty-vs-settled ticks)
- Prefer **run-to-run consistency** over single-day hero metrics
- Export **framework-agnostic** digests (Markdown + JSON), not product-Mongo dumps

### 1.3 Trace → feedback → eval → recommend flywheel

Patterns from [OpenAI agent improvement loop](https://developers.openai.com/cookbook/examples/agents_sdk/agent_improvement_loop),
[agent-eval trajectories](https://github.com/tangle-network/agent-eval), and harness digests
([AHE](https://github.com/teddytennant/agentic-harness-engineering)):

1. Collect evidence (traces / status snapshots / digests)
2. Attach analysis (what mattered, failure class)
3. Distill reusable expectations (eval / lesson / playbook patch)
4. Emit **ranked, how-to recommendations** with evidence links
5. Keep a growing archive so the next day compares against history

Digests must be **staff-audit quality** (executive brief + per-item analysis), matching our existing
self-improve contract (`catalog:self-heal --digest` / HiTL). Never a counter dump.

### 1.4 Do not crown a single “best agent” across domains

Heterogeneous content types make absolute leaderboards misleading. Best practice:

| Compare fairly | Do not compare as if identical |
| --- | --- |
| Ops fitness for Cursor / Cloud Agent (timer reliability, docs honesty, ingest-only) | Raw “listings published today” across sparse Africa vs dense US |
| Consistency of process (defer FIND when debt hot, evidence bar) | Domain-specific KPI without a content profile |
| Recommendation quality (actionable how-to, doctrineOk) | Model vanity metrics |

Use **per-agent SWOT** + **normalized dimension scores** + an **environment-fit ranking** that is
explicitly about how well the agent works *in this operating environment*, not which vertical is
“more successful.”

### 1.5 SWOT adapted for content agents

| Quadrant | Meaning here |
| --- | --- |
| **S** | Proven strengths this period (evidence-backed wins, reliable ticks) |
| **W** | Repeated failure classes, doc drift, quarantine debt, honesty risks |
| **O** | Portable contracts to adopt from siblings; unused public APIs; twin patterns |
| **T** | Cross-client contamination (schedule shapes), engine divergence, force-push risk, inventing facts |

Recommendations close the loop: each Weakness/Threat gets a **fix** + **how** + **owner folder**.

### 2.2 Content-type profiles (why unique approaches matter)

#### Padel Africa — sparse discovery catalogue

- **Unit of content:** venue listing (courts, hours, contacts, About, media)
- **Honesty bar:** never invent phones/emails/ages/court counts; FIND evidence grade required
- **Schedule:** management `RecurringSlot` singular `weekday`
- **Jobs:** about-curate → quality-loop → media (R2/ImgBB) → hygiene → reconcile → FIND → self-heal digest
- **Outcome signals:** published count growth, FIND seeded vs zero-result, About debt, HiTL queue, process lessons
- **Working-env fit:** single orchestrator timer (`padel-find-tick` on padel chat); mature playbooks under `content.padelafrica/docs/`

#### Sportolok — dense directory + publish/delivery decisions

- **Unit of content:** sport listings + sovereign *decisions* (publish-approval, quality-gate, delivery priority, …)
- **Honesty / safety:** schedule contract is production-critical (outage from `weekdays[]`)
- **Schedule:** same management `RecurringSlot` as padel — shared trap, different density
- **Jobs (target):** ingest-only automation; historical Mongo sovereign runtime is **quarantined**
- **Outcome signals (once cutover):** decision agreement vs staff, delivery metrics, ingest success rate, schedule validation failures
- **Working-env fit today:** migration incomplete; weak until executor rewrite + core reconciles `release/sportolok`

#### ClassScout / Your Field — dense forever enrichment

- **Unit of content:** activity providers (programs, trials, boroughs, age, price, contacts)
- **Honesty bar:** evidence-only; unpublished contacts stay blank; `generated_art_only` media default
- **Schedule:** `recurringPrograms[].daysOfWeek` (Monday…Sunday) — **not** RecurringSlot
- **Jobs:** `catalog-loop:forever` (improve + find + self-heal defer + hourly rollup + weekly digest)
- **Outcome signals:** lasting-public rate, improve fill rates, find smoke, Tier A auto-pauses, scarcity briefs
- **Working-env fit:** forever loop is dense-native; sparse timer twin exists for Cloud Agent; agents must not merge forever-Find with padel until-found engines

### 2.3 Shared non-negotiables (all three)

1. Agent home = `content.<client>/` on `sovereign.content` `main`

3. No cross-imports between client folders

## 4. Design implications for our daily job

1. **Own the job in `fleet/`** (SC-central), not inside any `content.*` folder.
2. **Content profiles** encode density, growth mode, schedule family, honesty bar, and fair KPIs.
3. **Two scorecards:** (A) working-environment fitness, (B) content-outcome fitness — never conflate.
4. **SWOT per agent daily** + comparative narrative (“who is better *for this ops environment*”).
5. **Recommendations** are per-agent, how-to concrete, doctrineOk, routed to the right folder/chat.
6. **Growing knowledge:** `fleet/digests/YYYY-MM-DD.{md,json}` + rolling `fleet/memory/latest.json`.
7. **Cadence:** one daily Cursor timer on the SC-central agent (do not steal padel/classscout timers).
8. **Honesty:** if signals are missing, say so — do not invent outcomes.
